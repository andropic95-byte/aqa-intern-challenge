# Тестовое задание AQA Учи.ру

Исправленные тесты виджета поддержки на [uchi.ru](https://uchi.ru).
Исходный проект: [uchiru/aqa-intern-challenge](https://github.com/uchiru/aqa-intern-challenge).

## Запуск

Нужны Node.js 22.14 и npm. Версия Node.js указана в `.nvmrc`.

```shell
npm ci
npx playwright install chromium
npm test
```

Запуск с открытым браузером:

```shell
npm run test:headed
```

Просмотр HTML-отчета:

```shell
npm run test:report
```

При падении теста в `test-results/` сохраняются скриншот и trace.
Тесты работают с настоящим сайтом и требуют доступа к Учи.ру и сервису поддержки.

## Что исправлено

- `getPopularArticles()` возвращает `Locator` вместо массива из `all()`.
  Список загружается асинхронно, а `all()` не ждет появления элементов.
  Теперь клик по первой статье использует автоматическое ожидание Playwright.
- Кнопка «Написать нам» определяется по `data-test="button_feedback_form"`.
  Селектор `[class^=btn]` был слишком широким и находил в том числе элементы оценки статьи.
- Заголовок проверяется через `toHaveText()` с ожиданием обновления текста.
  Проверка значения, полученного через `textContent()`, могла читать предыдущий заголовок.
- Cookie-баннер ищется по состоянию `.show`: скрытая копия баннера не участвует в выборе кнопки.
- Корневой элемент виджета определяется по наличию кнопки `openWidget`,
  без зависимости от класса компонента `dino-typography`.

## Сценарии

1. Открытие виджета и отображение заголовка базы знаний.
2. Переход из популярной статьи к форме «Связь с поддержкой» и проверка заголовка.
3. Дополнительный тест: закрытие виджета крестиком и повторное открытие.

Тесты не отправляют обращения в поддержку.
